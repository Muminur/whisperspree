# T2.1 Hotkey manager plan

## Scope

Complete the FR-1.3 input boundary without creating a second session owner: the
platform listener emits compact key edges, `HotkeyManager` applies PTT/toggle,
Esc, debounce, speech-aware accidental-tap, and permission-degradation policy,
and one action bridge calls the managed `DictationRuntime`.

## Current implementation and remaining work

The policy core, rdev forwarding, control channel, live settings conversion,
speech-observed signal, and revocation cleanup are implemented and tested.
Production still needs the macOS Input Monitoring probe, global-shortcut
registrar, acknowledged rebind/rollback, one shared action bridge, and setup
bootstrap. These depend on the complete R1 capture/VAD/ASR runtime and must not
be represented as complete until that gate passes.

## Required tests

- exact 199/200 ms accidental-tap boundaries with and without observed speech;
- debounce from confirmed Idle, repeated key suppression, Right-Option mapping;
- permission revocation cancellation and listener degradation/retry;
- toggle registration conflict rollback;
- persisted rebinding with live action and persistence rollback;
- PTT, toggle, and IPC dispatch through the same runtime.

## Constraints

The rdev callback only copies a compact event to a channel. Both PTT and toggle
remain gated by Input Monitoring. Registration failures map to `HK-PERM`, and a
failed live rebind must leave both the old persisted setting and old binding
active. Manual Finder/permission validation belongs to QA-3/R2.
