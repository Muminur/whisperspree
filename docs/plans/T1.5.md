# T1.5 Session state machine plan

## Boundary

Implement `pipeline::session` as the single owner of one dictation session. It consumes hotkey/VAD/context inputs, drives the `SpeechRecognizer` boundary from T1.4, and emits the typed §9.2 session events. OS microphone, frontmost-app, and injection surfaces remain traits so tests use deterministic doubles.

## State and invariants

- States: `Idle`, `Listening`, `Finalizing`, `Injecting`, `Cancelled`, `Error`.
- Enforce SM-1 with an explicit transition table: a second hotkey-down is ignored except Esc in `Listening`; illegal transitions return a stable error without mutating state.
- Enforce SM-2 by opening the microphone only on `Listening`/`Finalizing` and closing it on all terminal states within the session command.
- Emit `session:state` before any event associated with the destination state (SM-3).
- On release, retain up to `TAIL_MS=300` of audio before finalize (SM-4).
- Capture `AppContext` at start and again before injection; use current target with start-time style, and force clipboard-only when secure input is active (SM-5).

## Concurrency

The session coordinator owns mutable state on one async task. The audio callback only writes into the bounded ring/queue; it performs no allocation, locks, or ASR work. ASR decoding remains on the blocking worker from T1.4. Cancellation aborts the recognizer and closes capture before terminal events.

## TDD matrix

Write transition-table tests before production code: legal start/release/finalize/inject/idle paths; duplicate hotkey suppression; Esc cancellation; illegal transitions; state-event ordering; microphone lifetime; 300 ms tail; silence-only (<600 ms) notice/no history; context snapshot and secure-input clipboard fallback; ASR error propagation and cancellation. Add integration tests over real ring/VAD/recognizer interfaces with only OS surfaces doubled.
