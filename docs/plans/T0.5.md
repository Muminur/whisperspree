# T0.5 remediation plan — IPC state, command adapters, and real event emission

## 1. Scope and decision

T0.5 remains a foundations task. Its production scope is limited to the PRD
§9.1 command registry and TypeScript mirror, the §9.2 typed event helpers, the
completed T0.3 settings/keychain adapters, and the synchronization/coverage
checks needed to prove those contracts. It must not implement T0.0 repository
policy remediation or any T1.1 audio behavior.

The command split is:

- Make exactly these five completed T0.3 adapters functional now:
  `get_settings`, `update_settings`, `set_api_key`, `has_api_key`, and
  `delete_api_key`.
- Keep every other §9.1 command registered. Commands whose owning service has
  not been implemented continue to return `ApiError { code: "TODO", ... }`, as
  T0.5 explicitly permits.
- Keep the T0.4-backed command families registered but `TODO`. The database
  primitives exist, but §9.1 does not define complete add/update DTOs or return
  shapes for dictionary entries, snippets, custom prompts, or app rules. The
  later task table also assigns their end-to-end behavior to T4.2, T5.1, T5.2,
  T6.1, and T6.2. Inventing wire schemas in M0 would violate PRD §0.1.
- In particular, do not partially expose history deletion in M0.
  `store::history::delete_dictation` and `clear_history` return database-sourced
  paths for a caller to unlink; a complete adapter must route those paths
  through `confine_to_audio_dir` to satisfy §12 P-6. T6.1 owns history
  list/search/detail/delete/clear/export, and T6.2 owns `get_audio_url` and the
  shared app-audio-directory contract.

This decision interprets “command registration deferred to T0.5” in the T0.3
and T0.4 completion notes as exposure in the §9.1 registry, not permission to
invent underspecified M4–M6 payloads.

The later ownership map is explicit:

| Registered `TODO` family after T0.5 | Owning task |
|---|---|
| custom-prompt CRUD, app-rule CRUD, and `list_personas` | T4.2 |
| `reprocess_dictation` and `list_templates` | T4.3 |
| dictionary-entry CRUD | T5.1 |
| snippet CRUD | T5.2 |
| `list_dictations`, `get_dictation`, `delete_dictation`, `clear_history`, and `export_history` | T6.1 |
| `get_audio_url` | T6.2 |

The remaining registered stubs retain their own task-table owners (for
example model commands in T1.3, input-device enumeration in T1.1, permissions
in T2.5, and injection testing in T2.2); none is pulled into this remediation.

## 3. Current external documentation consulted

Retrieved 2026-08-09, against the versions resolved in
`src-tauri/Cargo.lock`: `tauri 2.11.5`, `tauri-macros 2.6.3`, and
`tauri-runtime 2.11.3`.

- Tauri `Builder::manage`:
  <https://docs.rs/tauri/2.11.5/tauri/struct.Builder.html#method.manage>
  — managed values require `Send + Sync + 'static`; mutation therefore needs
  interior mutability, and `State<T>` is injected into command handlers.
- Tauri `State`:
  <https://docs.rs/tauri/2.11.5/tauri/struct.State.html>
  — command state is a borrowed guard over the single managed value.
- Tauri `Emitter::emit`:
  <https://docs.rs/tauri/2.11.5/tauri/trait.Emitter.html#method.emit>
  — payloads require `Serialize + Clone`, emission returns `tauri::Result<()>`,
  and `AppHandle<R>` implements the trait.
- Tauri `Listener::listen`:
  <https://docs.rs/tauri/2.11.5/tauri/trait.Listener.html#tymethod.listen>
  — `AppHandle<R>` can receive app-target events using a `Send + 'static`
  callback, which is the production-path assertion the event integration test
  must exercise.
- Tauri test module:
  <https://docs.rs/tauri/2.11.5/tauri/test/index.html>
  — `mock_builder`, `mock_context(noop_assets())`, `MockRuntime`, and
  `get_ipc_response` are available only with the crate's `test` feature.
- Tauri “Calling Rust from the Frontend”:
  <https://v2.tauri.app/develop/calling-rust/>
  — synchronous commands run on the main thread unless forced async;
  asynchronous commands run as separate tasks, borrowed `State<'_, T>` is
  supported when the command returns `Result`, and all commands must be passed
  to one `generate_handler!`/`invoke_handler` call because a later
  `invoke_handler` replaces the earlier handler.
- Tauri `async_runtime::spawn_blocking`:
  <https://docs.rs/tauri/2.11.5/tauri/async_runtime/fn.spawn_blocking.html>
  — accepts an owned `FnOnce() + Send + 'static`, runs it on the executor
  dedicated to blocking operations, and returns Tauri's awaitable
  `JoinHandle<R>`.
- Tokio `task::spawn_blocking` behavior underlying Tauri's runtime:
  <https://docs.rs/tokio/1.53.1/tokio/task/fn.spawn_blocking.html>
  — short-lived blocking filesystem/keychain work belongs on the blocking
  pool; blocking inside an async worker can starve other futures, and a joined
  task can fail after panic/cancellation. The implementation uses Tauri's
  public runtime wrapper rather than adding Tokio as a direct T0.5 dependency.

The corresponding locally resolved crate sources were also checked at
`tauri-2.11.5/src/app.rs`, `manager/mod.rs`, `event/listener.rs`,
`async_runtime.rs`, and `test/mod.rs`. They confirm that app emission serializes
the payload and then dispatches to Rust listeners, and that awaiting Tauri's
blocking `JoinHandle` yields `tauri::Result<T>`. A listener registered before
the helper call can therefore assert the exact serialized payload without a
native window or network, while join failures can be mapped without formatting
their potentially sensitive panic payloads.

No new runtime dependency is needed. The existing Tauri dependency may enable
the `test` feature only in `[dev-dependencies]`; that feature must not be added
to the release dependency feature set.

## 4. Security and adapter design

### 4.1 Central recursive settings-secret rejection

P-3 must be enforced by `SettingsStore::update`, not only by the Tauri wrapper.
The store is the central persistence boundary and §8.3 deliberately preserves
unknown fields, so an untrusted runtime patch such as a nested `apiKey`,
`token`, `secret`, or secret-shaped string would otherwise be written to
`settings.json` unchanged.

Add one recursive reject-by-ignore pass in
`src-tauri/src/store/settings.rs`. It returns whether a JSON value is safe to
retain and handles every depth:

- For objects, remove a member only when its normalized field name denotes an
  explicit secret-field word or compound alias. Tokenize first at camel-case
  transitions (including acronym-to-word boundaries) and the `_`, `-`, `.`,
  `/`, and whitespace separators, then case-fold the lexical segments. Reject
  the adjacent compounds `api key` and `pass word`, plus the exact secret words
  `token`, `secret`, `password`, `credential`, `credentials`, and
  `authorization`. Explicitly cover `apiKey`, `api_key`, `api.key`,
  `anthropic-api-key`, `accessToken`, `access_token`, `apiCredential`,
  `api.credentials`, `authorization`, and `authorizationHeader` across case
  variants. After case-folding, also reject the separator-free whole-field
  aliases `apikey`, `accesstoken`, `apicredential`, `apicredentials`, and
  `authorizationheader` by exact equality. Never apply those compact spellings
  as substrings of a longer lexical segment.
- Do not implement the field check with naive `contains` matching. Preserve
  benign words whose lexical segments are not secret aliases, including
  `tokenizerModel`, `secretaryMode`, and `passwordlessMode`, along with their
  values. Do not invent irregular case-split aliases: `toKen_value` tokenizes as
  `to`, `ken`, `value` and is not a token field, while the intentional compounds
  `accessToken` and `access_token` remain covered. Nested variants cannot bypass
  the rule, but unrelated unknown fields and safe siblings must retain their
  existing shape.
- For strings, reuse the P-3 detector already pinned by `error::redact`: if
  `redact(value) != value`, remove that value rather than persisting the
  redaction marker. This covers the normative `sk-ant-...` and `Token ...`
  secret shapes without maintaining a second divergent detector.
- For arrays, recursively remove unsafe elements and sanitize objects nested at
  any array depth; do not allow either a secret string or a secret-field alias
  to bypass the guard merely by being wrapped in an array.
- Numbers, booleans, null, safe strings, safe arrays, and safe unknown object
  members remain byte/shape preserving under the existing merge semantics.

Run the pass on the incoming patch before validation/deep merge and again on
the fully merged raw object immediately before the serde round-trip and atomic
write. The second pass scrubs a pre-existing unknown secret on the next update
and is defense in depth against future merge changes. Rejection is silent and
returns the resulting valid `Settings`, consistent with Q8's established
validation/reject-by-ignore policy; it does not invent a fifteenth §14 code and
never logs the removed field name or value.

### 4.2 Owned managed state and blocking execution

Add a single public `IpcState` type beside the command wrappers (or in
`ipc/state.rs` if that keeps the module smaller) with cloneable owned handles:

```rust
pub struct IpcState {
    settings: Arc<Mutex<SettingsStore>>,
    key_store: Arc<dyn KeyStore>,
}
```

Construction accepts the owned store and key-store handle rather than
discovering dependencies inside commands. It performs the settings wrapping
internally so production and tests cannot accidentally construct a different
state shape:

```rust
pub fn new(
    settings: SettingsStore,
    key_store: Arc<dyn KeyStore>,
) -> Self {
    Self {
        settings: Arc::new(Mutex::new(settings)),
        key_store,
    }
}
```

Production calls `IpcState::new(SettingsStore::new(store::app_data_dir()),
Arc::new(KeyringStore))`. Tests call the same constructor with a real
temporary-directory `SettingsStore`; neither caller wraps the settings store
itself. Any new in-memory, failing, thread-recording, or access-counting
`KeyStore` used by the IPC audit is defined inside
`src-tauri/tests/ipc_state_integration.rs`; it must not be added to the shipping
`src-tauri/src/testutil` module. A compile-time
`assert_send_sync::<IpcState>()` pins Tauri's managed-state requirement.

Use `std::sync::Mutex`, not an async mutex: the underlying T0.3 methods are
synchronous and execute only inside the blocking pool. Both `get_settings` and
`update_settings` clone the same `Arc`, and the blocking closure holds the lock
for the complete read/merge/validate/write transaction. Locking only the final
rename permits two patches to read the same base and lose an update.

All five T0.3 command adapters must leave the Tauri main thread. Define them as
async commands returning `Result<_, ApiError>` (the documented borrowed-State
workaround), clone the required `Arc` handle before the first await, and invoke
the synchronous filesystem/keychain operation only inside
`tauri::async_runtime::spawn_blocking`:

```rust
#[tauri::command]
pub async fn get_settings(state: State<'_, IpcState>) -> Result<Settings, ApiError>;

#[tauri::command]
pub async fn update_settings(
    state: State<'_, IpcState>,
    patch: Value,
) -> Result<Settings, ApiError>;

// set_api_key / has_api_key / delete_api_key follow the same owned-Arc pattern.
```

Annotating a synchronous handler with `#[tauri::command(async)]` would meet the
minimum main-thread requirement, but it is insufficient by itself for this
design: blocking filesystem/keychain work inside an async worker can still
starve the runtime. The required implementation is async command plus
`spawn_blocking`. Managed state is not a JSON argument, so frontend envelopes
remain `{ patch }`, `{ provider, value }`, and `{ provider }`.

Wrap blocking joins in one private await/flatten helper that accepts the
`tauri::async_runtime::JoinHandle<Result<T, Error>>` returned by
`spawn_blocking`. A successful join maps its inner error through the IPC
mapper. Any failed join must become `DB-IO` with the exact constant message
`"IPC blocking task failed"`. Never format or log the Tauri/Tokio join error:
a failure can carry runtime or panic detail that is not safe for IPC or logs.

Exercise this real failure branch without any panic. Spawn a permanently
pending Tauri async task with the same output type, retain its `JoinHandle`,
call `abort()`, and pass that cancelled handle through the exact same private
await/flatten helper used by all five `spawn_blocking` adapters. Because the
future can never complete normally, awaiting it deterministically takes the
join-error branch. Assert the exact constant `DB-IO` response and that no
rendering of the join error appears. The test must not panic or install,
replace, or suppress the global panic hook. A poisoned settings lock likewise
becomes a constant-message `DB-IO`; do not format the `PoisonError`, unwind, or
recover a potentially inconsistent guard.

### 4.3 Non-echoing provider parsing and warning mapper

`Provider` may derive `Serialize`, but it must not derive `Deserialize`.
Implement `Deserialize` manually by first deserializing to
`serde_json::Value`, then matching only `Value::String("anthropic")` and
`Value::String("deepgram")`. Every other value -- including an unknown or
secret-shaped string, null, boolean, number, object, and array -- returns the
same constant `D::Error::custom("unsupported provider")`. Do not use Serde's
`unknown_variant`, `invalid_value`, or a visitor whose default diagnostics can
render the rejected input. This prevents attacker-controlled values from being
echoed by Serde/Tauri before the command wrapper or redaction mapper runs.
Syntactically malformed JSON that fails before a JSON value exists remains a
transport parse failure, outside this closed-domain conversion. A rejected
provider value must not call `KeyStore`.

The internal `Error -> ApiError` mapper must:

1. derive the stable code and redacted message through `ApiError::from(&error)`;
2. emit exactly one `WARN` event containing only the stable code and the
   already-redacted message;
3. return that same `ApiError`.

The warning invariant must be tested with a raw tracing subscriber/layer inside
`tracing::subscriber::with_default`, before `RedactingWriter` can mask a bug.
The captured event must already be `WARN`, contain the correct code and
`[REDACTED]`, and contain neither raw secret. This mapper is used for store,
keychain, poisoned-lock, and constant join-failure errors. The `value` argument
to `set_api_key` is never formatted, traced, copied into a `TODO` message, or
passed to `SettingsStore`.

Key absence remains non-error behavior: `has_api_key` returns `false`, and
deleting an absent key succeeds. Q8/Q6 still govern `DB-IO` and recoverability.

### 4.4 One shared production/MockRuntime builder configuration

Extract one generic builder function used by both `run()` and all MockRuntime
command tests:

```rust
pub fn configure_ipc<R: Runtime>(
    builder: tauri::Builder<R>,
    state: IpcState,
) -> tauri::Builder<R> {
    builder
        .manage(state)
        .invoke_handler(tauri::generate_handler![/* all 42 commands once */])
}
```

The order is load-bearing: install exactly one managed `IpcState`, then install
exactly one handler registry containing all 42 commands. Tauri permits only one
value per managed type and only the last `invoke_handler` call is active.
`run()` must call `configure_ipc` rather than maintain a second registry, and
MockRuntime state/dispatch tests must call the same function rather than build
a test-only subset. This prevents tests from passing against wiring that
production never uses and proves the five adapters retrieve the one injected
state. The existing single-instance plugin remains first in production before
the shared IPC configuration.

`src-tauri/tests/common/mod.rs` owns the one canonical reusable
`IpcHarness` constructor used by `ipc_state_integration.rs` and the existing
`ipc_command_dispatch.rs`. The constructor accepts an `IpcState` created from a
real temporary `SettingsStore` plus an integration-test-local
recording/failing `KeyStore`, calls only
`configure_ipc(mock_builder(), state)`, builds with
`mock_context(noop_assets())`, creates one webview, and exposes one invoke
helper. Each test may construct a fresh harness for isolation, but every
harness contains the full production 42-command registry; related dispatches
within a test reuse that one app and webview. No integration fixture may call
`.invoke_handler(...)` directly or install a subset. Revise the existing
`ipc_command_dispatch.rs` cases to import `mod common` and use this
full-registry harness, so the retained nested-envelope regression does not
preserve a parallel test-only handler list. Success/failure/access recording
types remain in `ipc_state_integration.rs`; the common harness accepts their
trait-object handle, and none enter shipping `src-tauri/src/testutil`.
