## 4. Trust boundaries and policy interfaces

Keep one standard-library raw-object engine in `scripts/repo_policy.py`. Shell files are thin, fixed-argument adapters that invoke `/usr/bin/python3`; Git plumbing uses the audited `/usr/bin/git` with a constructed environment. Local hooks/wrappers are advisory same-user feedback. The authoritative PR decision is the default-branch `pull_request_target` workflow, which treats every head object and all event strings as data.

Required engine responsibilities (names may change, behavior may not):

- `validate_repository(root, expected_remote)`: require one canonical repository identity, exact `origin` fetch URL, no `pushurl`, no credentials, no URL rewrites/custom helpers, and no conflicting multi-values. PR/push event `repository.full_name` and PR `base.repo.full_name` must equal `Muminur/whisperspree`.
- `fetch_pr_objects(root, event)`: validate duplicate-free bounded JSON; require `pull_request.number` to be a positive integer with `bool` rejected; require full base/head OIDs; require checked-out `HEAD == base.sha`; validate the event's same-repository/fork head-identity fields are internally consistent with the canonical base relationship before any fetch; fetch **from the canonical base repository only** using `refs/pull/<number>/head:refs/whisperspree-policy/pull/<number>/head`; verify the fetched object is a commit exactly equal to `head.sha`; never pass `head.repo.clone_url`/SSH URL/API URL as a Git transport; never checkout it.
- `load_trusted_manifest(source)`: obtain authorization from the trusted base tree, never from the candidate head/worktree. PR uses the checked-out base blob; push uses the `before`/trusted-default blob; pre-push uses the verified canonical remote-tracking default-branch blob and fails closed if missing/stale/unrelated.
- `iter_introduced_commits(base, head, kind)`: stream every head-side commit, including merge commits, without small count ceilings. New branches/tags derive trust from canonical default-branch reachability rather than scanning all repository history.
- `iter_commit_changes(commit)`: expose parent-aware raw A/M/D/T tuples for every introduced commit so add-then-delete, delete-then-readd, intermediate policy changes, and merge commits cannot disappear in an endpoint-only diff.
- `iter_commit_entries(commit)`: stream raw path/mode/OID and blob bytes without checkout, external diff, textconv, filters, or head-defined executable/config.
- `scan_metadata(...)`: apply both attribution and secret rules to PR title/body, every introduced commit message, and annotated-tag metadata. Diagnostics identify only metadata class/rule, never matched content.
- `scan_entries(...)`: independently evaluate governance/environment leakage, secret rules, object type/mode, and policy transition authorization. One exact secret exception suppresses only its exact `(path bytes, mode, oid, rule)` finding and never short-circuits another rule or entry.
- `pre_push(remote_name, remote_location, stdin)`: validate the two official hook arguments and configured origin identity; consume every ref record; reject deletion/non-fast-forward; scan metadata, every intermediate commit/blob, governance, and v2 transitions with the same semantics as CI.

The canonical GitHub base PR ref is the topology invariant: fork contributors push their branch to the fork, but GitHub publishes `refs/pull/<n>/head` in the **base repository**. Tests must reproduce that layout; placing `refs/pull/<n>/head` in the fork remote is an invalid fixture.

## 5. Strict trusted-manifest v2 protocol

`.repo-policy-secret-exceptions.json` is a policy surface and the sole authorization document. Remove the legacy `--exceptions` protocol and self-issued `.git` approvals so PR, push, and pre-push all parse the same v2 model.

The trusted-base manifest contract is:

- A regular non-symlink `100644` blob, bounded to `MAX_MANIFEST_BYTES`, UTF-8 JSON, duplicate keys rejected at every depth.
- Exact top-level keys: `version`, `secret_exceptions`, `policy_transitions`; `version` is integer `2` with booleans rejected; no unknown keys.
- Each list is bounded by manifest bytes, not an arbitrary 16-entry count; duplicate tuples are rejected.
- `path_b64` is canonical base64 for non-empty raw Git path bytes with no NUL; modes are exact permitted Git blob modes; OIDs match the repository object format and referenced new objects must be regular blobs of the declared mode.
- Secret exception tuple: exactly `(path_b64, mode, new_oid, rule)` with a closed rule id.
- Transition tuple: exactly `(path_b64, status, old_mode, old_oid, new_mode, new_oid)`; status is `A|M|D|T`, zero mode/OID appears only on the absent side required by status, and every nonzero object is type/mode verified.

Authorization rules:

1. A manifest-only PR is the non-recursive preauthorization anchor. Across **every introduced commit**, it may change only `.repo-policy-secret-exceptions.json`; the endpoint must be exactly one regular `100644` manifest blob; its head blob must itself pass the strict bounded v2 parser and raw secret scan. A temporary/mixed nonmanifest change that is later removed still rejects the PR.
2. An ordinary target PR may not modify the manifest. Every policy A/M/D/T tuple observed at each commit boundary must appear exactly in the base manifest; path/mode/OID/status drift rejects.
3. Push and pre-push use identical tuple validation and trusted-base selection. They cannot use the pushed/head manifest to authorize that same change. The only special case is a strict manifest-only transition as defined above.
4. Add, modify, delete, type change, rename-as-delete+add, intermediate change, and merge commit are all explicit transitions. Endpoint neutrality never erases history.
5. Consumed entries are removed later through a separate strict manifest-only cleanup PR.

## 6. Bounded streaming, cleanup, and workflow shape

Replace `list` accumulation and per-command 30-second timeouts with a single monotonic operation deadline plus bounded streaming:

- Event, manifest, hook stdin, ref/metadata record, and policy-surface blob sizes have explicit fail-closed maxima. Ordinary blobs are scanned in bounded chunks so future WAV/fixture commits are not rejected merely for exceeding 1 MiB.
- Pass one deadline through Git fetch, rev traversal, raw record parsing, `cat-file --batch`, metadata, and blob scanning. A producer that stalls before a newline must time out; a sequence of individually short commands may not extend the total without bound.
- Use nonblocking/selectable pipe reads or an equivalently proven standard-library mechanism, cap individual record length, preserve overlap/state for detector matches crossing chunk boundaries, and fail on incomplete UTF-8/JSON/raw records where the format requires completeness.
- On timeout/error, terminate then kill/reap child processes within a second bounded cleanup window; close pipes; delete secure temp files; remove isolated PR refs in `finally`; never accept an unscanned remainder.
- Keep failures content-free and do not print event JSON, refs containing attacker text, commit messages, blob bytes, transport credentials, or matched detector strings.

`.github/workflows/pr-policy.yml` remains `pull_request_target`-only, `contents: read`, default/base checkout only, full-SHA action pins, `persist-credentials: false`, no cache/artifact/package install, and no head execution. Its base scanner fetches the canonical base PR ref as raw objects and scans PR metadata plus all objects. Public-repository M0 canaries use unauthenticated canonical HTTPS. Private-repository fetching, when Q1 restores that state, may use only the job's read-only ephemeral token through a non-logging `--config-env`/environment channel: never argv, remote URL, persistent Git config, output, or a repository secret. Clear the variable/config channel and isolated ref on success and every failure. Never substitute a head-provided URL or weaken TLS.

`.github/workflows/ci.yml` executes ordinary PR code with no elevated policy authority. Push/tag policy must run before dependent release build; annotated and lightweight tags are scanned. Remote actions stay pinned to audited full 40-hex SHAs with provenance in `docs/DEPENDENCIES.md`.

`scripts/safe_git_commit.sh` currently resolves `python3` through `PATH` and calls a nonexistent `repo_policy.py commit` action. No non-test caller exists. Preferred resolution: RED-test caller absence and remove it plus legacy wrapper tests. If a verified caller appears, harden it to absolute executables, fixed arguments, the installed pre-commit/commit-msg checks, minimal environment, and fail-closed status before retaining it. It never becomes an authorization boundary.
