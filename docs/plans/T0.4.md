## `0001_init.sql` (byte-identical to §8.1)
Reproduce §8.1 exactly: both PRAGMAs, `schema_version` table + `INSERT … VALUES (1)`, all 7 tables, `engine CHECK IN ('cloud','local')`, every DEFAULT, `dictation_transforms.dictation_id … ON DELETE CASCADE`, `app_rules.custom_prompt_id … ON DELETE SET NULL`, `idx_dictations_created`.
- **PRAGMA placement (the trap):** `journal_mode = WAL` is a persistent DB property — running it once inside the migration suffices. `foreign_keys = ON` is **per-connection** and resets to OFF on every new connection; the migration runs only on a fresh DB, so relying on the in-file PRAGMA silently disables cascades on every later open. → `db::open` MUST `execute_batch("PRAGMA journal_mode=WAL; PRAGMA foreign_keys=ON;")` on **every** connection, in addition to the in-file PRAGMAs. Keep the in-file lines (spec fidelity) but never depend on them at runtime.
- **PRD ambiguities (flag, don't silently fix):** (1) `schema_version` has no single-row/PK constraint — the runner reads `MAX(version)`, never assumes one row. (2) §8.1 shows `0001` self-seeding `version=1`, but the forward-only policy ("applies files > schema_version") never says how version is bumped for `NNNN>1`. Conservative: runner sets `version` after each file. → **OPEN_QUESTIONS (Q-new)**.

## Interfaces (§9.1-derived; all `Result<_, crate::error::Error>`)
- `db::open(path:&Path) -> Result<Connection>` — open, apply per-conn PRAGMAs, run `migrate`.
- `db::migrate(conn:&Connection) -> Result<()>` — embedded `MIGRATIONS: &[(i64,&str)] = [(1, include_str!(...))]`.
- history: `insert_dictation(&Connection, &DictationRow)`; `get_dictation(&Connection, id) -> Option<DictationRow>`; `list_dictations(&Connection, q:Option<&str>, limit:i64 /*=50*/, before_id:Option<&str>) -> Vec<DictationRow>`; `delete_dictation(&Connection, id) -> Option<PathBuf>` (returns audio_path to unlink); `clear_history(&Connection) -> Vec<PathBuf>`; `insert_transform(&Connection,&TransformRow)`; `list_transforms(&Connection, dictation_id)`; `export_history(&Connection, w:&mut impl Write) -> usize` (JSON-lines, §9.1); `retention_sweep(&Connection, retention_days:u32) -> Vec<PathBuf>`.
- dictionary_entries: `list/insert/update/delete_dictionary_entry`. snippets: `list/insert/update/delete_snippet`. custom_prompts / app_rules: `list/insert/update/delete_*`. Each `insert`/`update` returns `Result<()>`, `delete` returns `Result<bool>`.

## Algorithm — migration runner
1. `open`: `Connection::open(path)` (map err → `db_io`), apply per-conn PRAGMAs, call `migrate`.
2. `migrate`: read current version = `0` if `schema_version` table absent, else `SELECT MAX(version)`.
3. For each `(n, sql)` in `MIGRATIONS` with `n > current`, in ascending order: `BEGIN` → `execute_batch(sql)` → `UPDATE schema_version SET version=n` (redundant-but-idempotent for `0001`, which self-seeds) → `COMMIT`. Any error rolls back the tx (partial migration never persists).
4. Up-to-date DB (`current == max`): loop body never runs → no-op, no rewrite.
5. Future/unknown version (`current > max known`): leave untouched, return `Ok` (forward-compat; a newer app wrote it) — do **not** error or downgrade.

## Algorithm — `retention_sweep`
1. If `retention_days == 0` → **no-op**, return `vec![]` (retention disabled; see edge cases).
2. `cutoff = chrono::Utc::now() - Duration::days(n)`, ISO-8601.
3. `SELECT audio_path FROM dictations WHERE created_at < cutoff AND audio_path IS NOT NULL` → collect.
4. `DELETE FROM dictations WHERE created_at < cutoff` — transforms vanish via `ON DELETE CASCADE` **only because** `foreign_keys=ON` is set per-conn (step in `db::open`).
5. Best-effort `std::fs::remove_file` each collected path (ignore `NotFound`; §12 P-6). Return the list for the caller/logger. Scheduling ("on launch + every 6 h", §8.1) is deferred to T0.5+.

## Edge cases (§8.1/§14/§12)
- **FK cascade needs per-conn PRAGMA** → covered by `db::open`; a dedicated test proves transforms actually delete.
- **`history.saveText=false`** (§8.1): session writes no row — enforced at the **caller** (T0.5 pipeline), not here; stores stay pure. Note in module doc.
- **`retentionDays=0`**: §8.3 clamps floor to 0 but §8.1 doesn't define 0's meaning. Conservative = **disabled/no-op** (never nuke all history on a boundary bug). → **OPEN_QUESTIONS (Q-new)**, `// PRD-QUESTION`.
- **UNIQUE violations** on `snippets.trigger` / `dictionary_entries.phrase` → map `rusqlite::Error` → `db_io()` (§14 `DB-IO`, closed matrix per Q8). Same for any SQLite failure.
- **`snippets.trigger` lowercase** (§8.1 "stored lowercase") has **no** SQL CHECK — normalization is app-layer; `insert_snippet` lowercases before binding.
- **delete unlinks audio** (§9.1/§12 P-6): `delete_dictation`/`clear_history` return paths; unlink is caller-side or a thin helper, best-effort.
- **`list_dictations` LIKE** searches **both** `raw_transcript` AND `processed_text` (§9.1); `limit` default 50; `before_id` → keyset page `WHERE created_at < (SELECT created_at FROM dictations WHERE id=?)` ordered by `idx_dictations_created`.

## Risks
- **`foreign_keys` per-conn trap** — highest-severity: cascade/set-null silently no-op if any code opens a `Connection` without the PRAGMA. Mitigated by centralizing all opens through `db::open` + the cascade/set-null tests that fail loudly.
- **`snippets.trigger` lowercase is app-layer only** — a future writer that skips `insert_snippet` can store mixed case; no DB guard. Documented; whole-utterance matching (FR-3.2) depends on it.
- **`retentionDays=0` semantics** — wrong guess could mass-delete history; chose the safe no-op and flagged it rather than delete-all.
- **`schema_version` multi-row** — no PK; always read `MAX`, never `SELECT version` (would break if two rows exist).
- **Version-bump policy for future migrations** unspecified by §8.1 — runner owns the bump; flagged so T-later migrations don't double-seed.
